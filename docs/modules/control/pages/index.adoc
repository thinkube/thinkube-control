= thinkube-control
:page-type: reference

_The control panel: what each of its pages does, and the operations it exposes to Claude Code as MCP resources and tools._

thinkube-control is one application with two faces. A FastAPI backend serves a React web interface, and the same backend is wrapped with `ExtendedFastApiMCP` and mounted at `/mcp`. Every operation listed on this page is reachable from the web interface and, by its `operation_id`, from Claude Code in Thinkube IDE. There is no second implementation.

It is a core component: the installer deploys it, and it redeploys itself through the same build loop as your applications.

This page lives in the `thinkube-control` repository, beside the code it describes, and is built into the documentation site with the rest.

== The pages

The sidebar has three groups.

image::control-dashboard-all.png[thinkube-control with the All Services dashboard open]

=== Dashboard

[cols="1,3",options="header"]
|===
| Page | What it shows

| Favorites | The services you starred. Empty until you star one.
| All Services | Every core component, optional component and deployed application, with its health, its category, a link to open it, its details, a restart button and a favourite star. The list comes from the services' own registrations; nothing is added by hand.
| Knative Services | Applications deployed with `type: knative`, which scale to zero.
| ai, applications, development, devops, security, storage | The same cards, one category at a time.
|===

Every card's *details* page shows the service's health status and the health history thinkube-control has recorded for it, and carries the *Service Enabled* switch. Switching a non-core service off scales it to zero; on brings it back. This is the switch that keeps an installed optional component from costing memory while you are not using it.

=== Deployment and infrastructure

[cols="1,3",options="header"]
|===
| Page | What it does

| LLM Gateway | The gateway endpoint, the GPU nodes with their slots and memory, the inference backends it has discovered, and every model in the registry with a *Load* and *Unload* control. xref:llm-serving.adoc[LLM serving and models] describes the mechanics.
| AI Models | The model catalogue. Mirror a model from Hugging Face into Thinkube Storage; watch the mirror job; delete a mirrored model.
| Templates | The template catalogue. Deploy a template by name or from a GitHub URL, follow a deployment's progress, and publish one of your applications as a template.
| Harbor Images | Two tabs. *Mirrored Images*: the public images the platform mirrored into Thinkube Registry, with their mirror date and per-architecture tags, and a control to mirror one again. *Custom Images*: images you define from a Dockerfile and build here.
| Optional Components | The catalogue of optional components with their requirements and whether each is installed. Install one; remove one. An installed component is switched off and on from its card's details page.
| Cluster Nodes | Every node with its role, architecture, memory, GPUs and version. Add nodes and remove nodes; see xref:install:adding-nodes.adoc[Add more nodes].
|===

=== Configuration and security

[cols="1,3",options="header"]
|===
| Page | What it does

| Jupyter Kernels | Notebook environments built from definitions. Start from the `fine-tuning` or `agent-dev` template, add packages, and build it for every GPU architecture in the cluster. A built environment appears as a kernel in Thinkube Notebooks.
| JupyterHub Config | The defaults a new notebook server starts with: node, CPU cores, memory and GPU count. The form shows what each node has, and the defaults cannot exceed it.
| Secrets | Secrets your applications read, and which applications use each one.
| API Tokens | Tokens for calling thinkube-control and the LLM Gateway from outside the browser. They start with `tk_`.
|===

== Calling it from outside the browser

The REST API is at `https://control.<your domain>/api/v1`, with its OpenAPI description at `/api/v1/docs`. Create a token under *API Tokens* and send it as `Authorization: Bearer tk_…`. The same token is accepted by the LLM Gateway.

Thinkube IDE arrives with this connection made: Claude Code's MCP configuration points at `https://control.<your domain>/mcp` with a token the installer created.
